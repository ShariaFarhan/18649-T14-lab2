# Lab 3 故障灯测试流程

当前版本：三节点心跳、双 CAN 去重、总线健康判断及 DEG_A/DEG_B。
20 秒全亮命令和开机亮灯自检已删除。代码未 commit、未 push。
此流程是待执行的实物验收，不是已经通过的测试记录。

## 灯对应

| 节点 | A 故障灯 | B 故障灯 |
|---|---|---|
| Pi / N1 | GPIO5，物理脚29 | GPIO6，物理脚31 |
| Front / N2 | D3 | D5 |
| Rear / N3 | D3 | D5 |

各灯串联330Ω；高电平亮。正常接线下六灯全灭。

## 每项统一操作

1. 从六灯全灭、两条总线均已连接的状态开始。
2. 只拔表中指定模块到总线的 CANH、CANL 两根支路线。
3. 保持约2秒观察并记录灯的状态。
4. 接回原位置，确认六灯恢复全灭，再进行下一项。

测试过程中保留供电、USB、SPI、公共地和总线终端电阻。
不用重启、重新烧录或重新启动程序。先完成全部单总线项目，再做隔离。

| 1 | Front A | Front D3 | 全灭 |

| 3 | Rear A | Rear D3 | 全灭 |

每一行完成后都恢复所有支路。完全隔离一个节点时，其余两个节点仍可
通过A/B互相通信，因此它们的总线灯不应亮，但会记录该节点心跳丢失。

## 怎么看异常

- 断A亮B：检查LED标注/接线，以及两块CAN模块A/B标签。
- 断一个节点的A，其他节点A灯也亮：检查是否拔断公共总线、移走终端，或接线实际是串接断路。
- 断H/L仍不亮：确认拔的是该模块的两根总线支路线；只拔一根可能仍有通信。
- 恢复后超过1秒仍不灭：记录哪颗灯，不要用重启掩盖恢复失败。
- 不要为“修复”读数随意短接CANH/CANL或改电源。

Pi终端查看当前状态：

```sh
tail -f /home/sfarhan/lab3-heartbeat-s1/health.log
```

正常为 `HEALTH DEG_A=0 DEG_B=0 missing=0x0 isolated=0`。
`DEG_A/DEG_B`是Pi自己的总线状态；`missing`按bit0/1/2表示N1/N2/N3丢失。
按Ctrl+C只退出日志查看，不停止后台监测程序。

## 时限与当前范围

软件按连续60ms没有新心跳判断失联，收到有效新心跳后恢复。
Handout的指示灯目标是故障点亮不超过60ms、恢复熄灭不超过100ms；
上述2秒等待只用于肉眼功能检查，不能作为毫秒级时限合格的证据。
最终时限需要测时点/示波器测量。

后续CTRL/BLINK阶段已接入四个转向灯、输入校验和正常状态恢复，见LAB3_CTRL_BLINK.md。
没有有效Proxy输入时仍显示STARTUP或输入失联，并可能四灯双闪。
电机/舵机输出、跨总线转发和完整system error验收仍留给后续阶段。
